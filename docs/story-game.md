# 互动故事首版

入口：启动工作台后访问 `/play`。三种开局共用同一存档结构：直接填写背景，AI 给候选背景，或输入需求及反馈迭代候选。确认背景才开始游玩。用户扮演主角，选择建议或自由输入行动。

## 规则

体魄、敏捷、洞察、交涉初始均为3，生命10。普通行动无需判定；需要检定时，由模型分析属性、难度10～18及失败伤害0～4，程序掷d20并比较 `骰子+属性 >= 难度`。模型必须依据确定结果叙述。属性成长、战斗技能和装备加成尚未加入。

开局选择故事模式（生命至少1）、冒险模式（死亡结束当前路线、允许回溯）、硬核模式（死亡结束此局、禁用回溯）。死亡规则开局后固定。数值显示和自动插图可以切换，不影响规则。

回溯从已完成回合创建路线，共享此前快照，不覆盖旧路线。失败文字请求保留 pending 和已掷骰子；相同请求重试不重掷、不重复新增完成回合。取消失败行动后同一回合的相同行动仍复用已判定结果。每局最多100次文字调用、20次图片调用；失败计数，分支不重置。开局前的背景候选为单独付费调用，不纳入尚未创建的单局预算。

每局存在 `fp_game_sessions` 的版本化JSONB快照中，回合在应用层只追加。这是独立游戏存档，不写入旧编剧项目或冒用正式资产审批。当前路线可以导出Markdown；自动改编剧本和写入正式领域资产库尚未接通。

## 插图网关

`.env` 可设置以下配置，修改后需重启应用：

```dotenv
GAME_IMAGE_API_URL=https://your-gateway.example/generate
GAME_IMAGE_API_KEY=your-key
GAME_IMAGE_MODEL=your-model
```

这是项目定义的HTTP网关契约，不保证任意供应商原生接口直接兼容。网关需适配其供应商；当前代码不指定某个真实生图平台。

POST JSON输入：

```json
{"model":"your-model","prompt":"画面描述","width":1024,"height":768,"references":[{"mime_type":"image/png","image_base64":"实际参考图内容"}]}
```

响应必须包含 `image_base64` 和 `mime_type`，支持PNG/JPEG/WebP；图片上限12MiB，不接受远程图片URL。配置密钥时使用 Bearer 授权。任务不自动重试。

关键节点自动生成，历史回合也可点击“画出这一幕”。参考图仅取目标回合祖先中的成功图片，保留首张和最近两张；不取另一条路线未来图片。当前是通用画面参考，尚无每个人物独立标准三视图或视觉质量自动评测，因此不能保证身份绝对一致。

图片位于忽略Git的 `data/game-images/<存档ID>/`。数据库清单保存回合、提示词、参考图片ID、模型、状态、文件名、格式和大小，供后续视频资产适配。备份游戏时需同时备份数据库与该目录，单独备份数据库不会包含图片文件。

## 执行与验证

先备份现有数据库，再显式执行 `.\.venv\Scripts\python.exe -m scripts.init_db`，新增0004迁移不修改旧业务表。非空游戏表禁止降级删除。应用仍要求单进程；同一存档的操作串行，不同存档不共用长等待锁，数据库事务不跨模型网络请求。

图片通过单进程 BackgroundTasks 异步执行，文字先返回。应用重启会把未完成图片标记为失败，用户可以手动重试。它不是可靠分布式队列；没有取消运行中的网络请求功能。

API 位于 `/api/game`：背景候选、存档列表/创建/读取、开局重试、行动、分支、展示设置、图片提交/读取、路线导出。模型输出经过Pydantic字段与数值边界校验；人物动机、事实遗漏和视觉一致性仍需真实模型评测。

测试：`tests/test_game.py` 覆盖规则、回溯、重复请求、失败恢复、图片隔离、真实参考字节和接口。真实PostgreSQL测试使用现有随机临时数据库fixture，不清空业务库。模拟模型和浏览器测试不能证明真实生成质量。
