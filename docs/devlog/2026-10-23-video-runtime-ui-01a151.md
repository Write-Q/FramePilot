# 视频运行状态与历史 UI

用户方向（主任务转交）：供应商未选定，本轮提供真实运行状态与只读历史，不伪造可执行的模型或生成按钮。

实现计划：独立 storyboard-video.js，服务注册/输出校验状态，按分镜方案查询视频任务历史；渲染仅用 textContent，切换项目/分镜/版本先清除旧记录。主 storyboard.js 添加 refresh/availability hooks，HTML 添加独立区块。新建隔离浏览器 mock 测试；不修改既有 media.js 或后端。

实际实现：新增独立视频服务状态与任务历史区块，GET `/video-adapters` 和 `/video-runs?version=`，后者使用 `{runs:[], selections:[]}`。展示排队/提交/查询/成功/失败/未知状态、镜号与版本、历史选用和服务编号；没有生成或播放入口。并行读取服务状态与任务，分别报告失败，切换项目/分镜/版本以及旧响应晚到时不显示过期列表。未修改既有 media.js。

验证：先运行新测试确认因媒体模块不存在失败；实现后 bundled Playwright + Edge 本地 mock 浏览器测试通过（1 passed）。覆盖无服务、输出校验未配、只读操作、历史版本标识、未知不自动重提、错误文本防 HTML 执行、项目切换清理、服务与历史错误提示、390px 无溢出、无 JS 异常。另补晚到响应隔离回归。此记录未提交。测试仅模拟接口，不代表真实供应商或视频质量验证。

## 播放器与任务操作阶段

主任务进一步授权：成功且后端提供真实已验证文件 URL 的任务可预览/选用；仍不增加视频生成入口。新增原生 video controls、preload metadata、playsInline，不自动播放；仅接受同源 HTTP(S) 且不含凭据的 URL。展示后端实际分辨率、实际时长、计划时长与有符号差值，提醒人工核对画面/动作/声音，不自动判定语义通过。

选用仅当前已确认有效版本、无脏稿、非只读、applicable 时开放，POST 固定 expected_version 后刷新。queued 可取消；submitting/submitted/polling 可标记未知，明确不取消供应商请求；polling 且有 external_id 才提供恢复原任务查询，不重新提交生成。操作闭包固定分镜身份，切换后拒绝旧操作。

验证：先新增播放器/选用测试并观察 0 个播放器失败，再实现。mock 浏览器通过播放器属性、同源过滤、实际参数/差值、旧版/脏稿/只读/未确认门禁、POST 选用版本、取消、abandon、recover-poll 操作及无自动 POST；播放器390px布局检查。真实可播放文件验证由主任务补充；此测试仅 mock，不声称视频可解码已验证。未修改 media.js 或共享 HTML；已提醒整合任务移除 HTML 原“不提供播放”的过期描述。
