# 视频审核后端

- 需求：真实技术信息与抽帧证据，内容状态默认待人工；人工记录追加保存，不自动选用视频。
- 决策：不接视觉供应商；采样在数据库事务之外执行，插入前按项目锁重新校验当前版本、校验和和幂等键。旧报告可读，旧版本不允许新增记录。
- 当前阶段：先写契约、真实 MP4 和隔离 PostgreSQL 测试，随后实现独立 0010 表与服务。测试夹具没有真实模型效果含义。
- 所属文件：inspection_schema.py、inspection_contracts.py、inspection.py、0010_video_inspections.py、test_video_inspections.py。
- 提交：由主任务整合提交，本子任务不提交或推送。

## 实现与验证

- 已实现 `InspectionService(store, runtime=None, frames=None)`：创建、列表、受控读取帧文件、人工记录追加。API 默认依环境配置使用相同 VideoFiles/MediaFiles 根目录；不公开 storage_key 或本地路径。
- 报告固定视频校验和、原分镜版本、技术实际/计划时长与画幅及最多十二张真实 JPEG。原视频全解码的尺寸/时长元数据经固定字节 checksum 校验后使用；本次采样再次由受控子进程真实解码。技术警告不代表语义失败或通过，音频与语义审核明确未执行。
- 报告每视频最多十份、人工记录每报告最多五十条；变参复用幂等键拒绝。当前有效分镜与来源、原视频文件存在且 checksum 匹配才允许新增；旧报告仍可读，旧人工记录保留。两表数据库 UPDATE/DELETE 保护，项目/视频/报告复合归属外键及插入 checksum/version 校验。
- 采样不持有数据库事务；采样后锁定项目重新校验。并发同请求只保存一份报告；失败或并发败者清理本次未引用帧，绝不覆盖其他文件。
- TDD：契约首先因模块缺失失败；坏抽帧模拟首先暴露 PlannerError，修复为安全 ProductionConflict 后回归通过。故障模拟只覆盖异常处理，未声称视觉模型效果验证。
