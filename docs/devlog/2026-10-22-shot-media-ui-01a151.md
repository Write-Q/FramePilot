# 分镜图片制作 UI

用户方向：按已授权媒体制作计划实现逐镜图片生成，供应商未选定，不发起真实生成请求。

分工：仅工作台媒体模块、HTML/CSS、主模块小范围 hook 与浏览器测试。沿用现有绿色浅色工作台样式；生成提示词作为独立草稿，不能修改已确认分镜。旧版、未确认、脏稿禁止生成与选用；未知结果不自动重试，响应丢失保留原请求幂等键。

实际改动：独立 `storyboard-media.js`，逐镜首帧/关键帧/尾帧、独立提示词草稿、尺寸、图像配置、候选图与选用、排队取消和运行中标记未知；视频区域明确显示未接入。主模块增加配置、可用性、编辑镜头和载入分镜 hook。缩略图只接受同源 HTTP(S)，文本通过 textContent 展示。跨项目/版本数据不匹配时隐藏旧候选；pending 请求跨镜头仍锁定原始 payload，显示原镜号。

验证：先运行测试观察缺少媒体模块导致失败，再实现。2026-10-22 使用 bundled Playwright + 本地 Edge，`node --test tests/storyboard-media-ux.test.cjs` 通过 1 项浏览器综合测试：未确认/脏稿/历史版门禁、提示词草稿、响应丢失后原 payload 恢复（切换镜头不改变请求）、选用、排队/执行中/结果未知提示、切换项目/镜头不展示旧候选、390px 无横向溢出、无 JS 异常。sandbox 内 Edge 启动受阻，已用受批准外部 sandbox 测试执行，所有页面请求均由本地测试 route mock 截获，未调用真实服务。

局限与下一步：此处为 UI mock 验证，不证明真实模型兼容性或图片质量；后端端到端整合由主任务完成。列表需提供 idempotency_key 以在刷新时消除已接收 pending。未提交、未合并；记录随功能整合。

复核修正：响应丢失且未到服务端的 V1 请求可能在保存 V2 后锁住页面。现允许新版本、脏稿或只读状态下“核对上次图片请求”，始终重发原版本与原幂等键，不能创建新请求意图；服务端明确返回 409 后清除 pending，新生成继续受确认/脏稿门禁限制。新增浏览器回归覆盖 V1 pending → 未确认且脏稿 V2 → 原键核对 409 → 清除锁定 → 确认后恢复制作。

真实整合验证：新增 `tests/test_media_browser.py` 和 `tests/storyboard-media-integration.test.cjs`。fixture 创建随机临时 PostgreSQL 库、隔离图片目录、本地 uvicorn；独立 ProductionStore worker 仅注入 Images 固定 PNG（16×9 绿色测试图），线程在收尾停止并关闭连接。真实页面加载全部脚本，UI 保存图像配置、提示词预览、提交队列、worker 生成、刷新选用、服务端 selected 校验、实际 PNG 与镜头缩略图加载、新版本过期候选不可选均通过。`pytest -q --tb=short tests/test_media_browser.py`：1 passed，只有现有 Starlette 弃用提示。检查了 `.runtime/storyboard-media-qa/desktop.png`、`mobile.png`，文字与操作清晰，390px 无横向溢出。测试使用的数据库 URL 通过 app.database 加载并仅在进程内设为 TEST_DATABASE_URL，无真实服务调用；不对业务库做迁移。
