# 编剧来源编号与结构纠正

## 授权、设计与取舍

- 用户明确同意上一轮建议：用来源片段编号回填引用、结构输出错误有限纠正，然后进入实际创作试用。不扩充其他功能。
- 采用模型调用边界协议：DeepSeek请求收到当前材料生成的来源目录；卡片与审核选择evidence_ref，程序校验编号/来源后回填现有evidence或quote。已有API、历史版本和导出格式不变；非引用协议的测试/外部Provider保持原契约。
- 原稿、用户要求和每条反馈分别切分，跨材料不拼接；片段长度不超过1000字符。AI建议和未知项无事实引用。编号真实存在只证明出处，不证明概括含义受该段支持。
- Pydantic字段错误/非法引用编号/完整响应中的JSON格式错误最多自动纠正一次。网络、HTTP错误、截断与内容过滤不自动重试；纠正仍走持久化预算闸门。
- compose/revise若正文与顶层字段有效而只有卡片错误，保留候选正文，通过独立采用节点只纠正卡片，继续保障重启手动重试不重写候选。错误超出卡片时才重新请求完整结果一次。不得静默删除多余字段后冒充模型合规输出。
- 沿用严格引用、正式版本更新和确认规则；纠正失败保留旧稿与检查点，不无限重试。
