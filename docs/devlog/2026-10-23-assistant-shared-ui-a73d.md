# 共享制作助手 UI

## 用户方向与任务边界

- 用户已确定：左侧连续对话、底部输入，右侧保留编剧/分镜/剪辑工作区；浅暖中性色和浅绿色，减少卡片层级。
- 本子任务只维护 `studio-ui.js`、`studio-ui.css`、`studio-ui.test.cjs` 和本足迹。三页适配、后端接口及提交推送由整合任务负责，未修改已有页面脚本。
- 使用 impeccable 的 craft floor；会话隔离、未知请求恢复、确认执行与移动端状态用真实浏览器和模拟 REST 检查。未调用真实模型，不能据此声称已验证模型效果。

## 已实现与证据

- 公共 `FramePilotStudio.mount` 包裹原工作区 DOM，不替换节点；提供 `setContext`、`refresh`、`setNotice`。
- 桌面 360px 会话栏、300–560px 拖拽与键盘调宽、收起恢复；小于 1024px 切换两个保留 DOM 的面板。
- 项目会话隔离、无项目会话延续、导航携带项目/分镜/会话；导航不会自动发起模型消息。
- REST 只采用实际可执行文本配置，发送固定模型版本及思考等级；纯文本呈现模型回复和预览。
- 未知请求保留原始载荷和幂等键；刷新仅 GET；明确重试才能重发。工作区脏状态阻止接受，拒绝仍可使用。
- 首轮 5 项测试通过；新增重载测试先复现跨页草稿丢失，修正为 sessionStorage 保存草稿。九项测试全部通过后，一次性检查桌面和手机截图，未发现共享 shell 的横向溢出或裁切。截图仅使用最小旧工作区 fixture，不代表三页实际整体验收。
- HTTP 200 但模型状态未知的测试先失败，修正后保留原请求信封及显式重试入口。整合发现后端完成状态是 `accepted`，新增创建项目用例并先复现失败；已兼容 `accepted` 与 `succeeded`，允许当前无项目会话通过自身 `writer_create` 的 accepted/unknown 状态绑定新项目，并通知工作区采用身份；其他跨项目读取继续拒绝。
- 运行中模型消息即使没有本地 pending 信封，也提供显式标记未知操作。执行中建议提供独立的 `/proposals/{id}/abandon` 操作；文案明确不会取消服务商请求。
- 文本输入最大 8000 字匹配接口；配置跳转携带当前上下文并指向实际 `#config-details`；待恢复请求显示固定的原模型版本与思考等级。
- 沙箱 Edge 进程无法启动，使用已批准的提升权限执行相同本地模拟测试。全程没有真实付费模型调用。
