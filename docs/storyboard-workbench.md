# 分镜工作台第一版

2026-10-23新增[图片制作与视频输入预览](shot-media.md)：保存并确认分镜后，可以逐镜生成静态帧候选、预览并选用。需要0008迁移与独立图片worker；供应商未选定，尚未验证真实图像/视频效果。下文早期0007及文字阶段说明保留历史范围，新安装应升级至head。

入口 `/storyboard`，也可从编剧项目的“进入分镜工作台”携带项目编号跳转。先确认当前剧本；未审核原稿直送不能直接生成。

## 使用

1. 显式升级数据库至 `0007_storyboard_reviews`（含独立文字审核）。应用启动不会执行迁移。已有数据按[数据库说明](database-foundation.md)先备份和演练，再停止写入并运行 `.\.venv\Scripts\python.exe -m scripts.init_db`。本轮开发仅迁移随机隔离测试库，未升级业务库。
2. 启动应用后，在工作台载入项目。添加文本配置：基础地址、模型名称、密钥环境变量名；只支持兼容 Chat Completions 的 JSON mode 文本协议。实际密钥放本机 `.env` 或环境，重启服务生效。配置只表示协议执行器存在，不证明网关或模型可用。
3. 设定镜头数（1—30）、画幅、可选风格与要求；点击生成，一次最多一个文本请求。不会自动修复、重试、生成图片或视频。每项目累计十次分镜请求（含失败/中断），与编剧十次分别计数。
4. 逐镜修改，必要时复制增加、删除或上下移动。可编辑原文依据、叙事任务、动作、人物、景别、机位、运动、构图、状态、对白、声音、节拍及静态帧/视频意图。对白格式为 `说话人｜原话`，节拍为 `秒｜动作`，各项每行一条。格式错误不会静默保存旧值。
5. 保存新版本后，阅读程序提醒并人工核对，再勾选审阅并确认。历史只读，修改后不继承旧确认。场次在一个系列内固定，需要调整场次时从剧本生成另一方案。

本标签页的未保存编辑用 sessionStorage 暂存，按项目/方案/版本隔离；不是正式存档。导出 JSON 会标识 unsaved_changes，正式版本以数据库为准。

## 执行与恢复

POST `/api/production/projects/{project_id}/storyboard-runs`：

```json
{
  "source_version": 1,
  "profile": {"profile_id": "实际配置id", "version": 1},
  "idempotency_key": "b95c3c3ce3644a3e9ad254b77a6db4da",
  "target_shots": 8,
  "aspect_ratio": "16:9",
  "visual_style": "",
  "instructions": ""
}
```

响应为运行记录，status 是 `running/succeeded/failed/abandoned`；不能仅凭 HTTP 201 判断生成成功。成功含 `board`、程序 `review`；失败只返回固定错误码/说明，不回显原始网关错误或密钥。相同键、相同参数返回原记录，换参数复用键返回409。服务固定模型配置版本，不随配置当前指针更新。

- GET `/storyboard-runs`：项目运行记录，用于刷新/重启恢复。客户端丢失 POST 响应时保留原键；对账发现终态后清理待核对状态。
- POST `/storyboard-runs/{run_id}/abandon`：显式标记中断，不是供应商取消。运行可能已计费，迟到的结果不会采用。同键仍不重发；发起另一请求前应核对外部服务。
- GET `/storyboards/{id}/review?version=1`：检查指定已保存版本，返回规则版本、定位和 warning，`semantic_verified=false`。

预约提交后才请求网络，网络期间无数据库锁；同项目一个运行。结果结构、镜头数、画幅、风格、来源引用和绑定通过校验后，重新检查来源确认及卡片/约束上下文，再在同一事务创建场次/分镜/镜头与成功记录。输出失败或来源变化不留下半份分镜。

进程在请求中退出会留下 running，由人工检查并标记中断；没有后台 worker 自动续跑。请求超时保存 `outcome_unknown`，不代表供应商确定未执行。运行预算按预约数计，不是已计费次数统计。

## Skill 与评估边界

运行组合本项目 K001 镜头规划、K002 空间连续性自检、K003 静态帧设计，当前各1.1.0；文件在 `app/production/skills/`，基于资料库来源自行编写。一次模型请求内组合，不冒充三次独立审核。记录原文/输入上下文摘要、确切模型配置 FK、提示词/schema/Skill 哈希、来源 ID及固定文件/章节。原1.0.0保留供历史哈希核对，更新细节见[第一步优化说明](storyboard-skill-refinement.md)。生成结果不可覆盖，人工修改通过新版表达。

程序提醒包括制作描述缺失、未使用场次、逐字引用覆盖、台词密度、动作数量和相邻计划状态差异。启发式只提醒，不证明剧情、空间、表演、时长或真实媒体正确。静态帧是文字描述，视频 prompt 是供应商中立意图；不是供应商可执行请求，未接图片、视频、参考资产服务。

验证记录见[开发足迹](devlog/2026-10-19-storyboard-workbench-01a151.md)。测试使用真实 PostgreSQL 与浏览器、确定性规划器及 HTTP MockTransport；尚未验证真实模型生成质量和各兼容网关差异。

## 独立文字分镜审核

为审核单独添加用途为“文字分镜审核”（`review`）、适配器为 `openai_chat` 的通用 API 配置，可使用与规划相同的模型地址，但配置身份分开。保存分镜后点击“审核当前文字分镜”，单独发起一次调用；不会在生成或保存后自动调用。审核结果不阻止人工确认、不自动改稿、不等于影像质量通过。

检查方向为剧情忠实、人物/道具连续性、空间关系、对白与时长、静态帧及信息缺口。报告提供严重度、待确认标记、定位、原文证据和建议。引文必须实际存在于固定剧本/镜头字段；这只证明引用存在，不证明模型推理正确。空问题列表显示“未报告问题”，不显示“通过”。

每次记录确切剧本/分镜/配置版本与提示词、schema、规则哈希。编辑保存新版、切换上游或改变创作卡/约束时，旧报告保留但标记过期；未保存修改也会显示不匹配并禁用重审。定位按钮只用于当前显示的同一分镜版本。

| 路径（前缀 `/api/production/projects/{project_id}/storyboards/{id}`） | 行为 |
| --- | --- |
| POST `/review-runs` | `expected_version`、固定 `profile`、16—64位 `idempotency_key`，显式一次审核 |
| GET `/review-runs` | 当前分镜系列全部历史，含 `applicable`、`stale_reasons` 与项目已用次数 |
| POST `/review-runs/{run_id}/abandon` | 标记中断，禁止采用迟到报告，不取消供应商执行 |

每项目最多十次独立审核，包含失败和中断，与编剧/分镜生成分别计数；同项目只允许一个进行中的文字审核。HTTP 201并非审核成功，需读取 `status`。网络响应丢失时保留同一幂等请求，先刷新记录；不要当作未计费或自动换键重发。进程退出留下的 running 需要人工对账后标记中断。

规则文件 `app/production/skills/storyboard-review-1.0.0.md` 与独立 `review_registry.json` 采用本地索引定位的 Toonflow reviewer/shotCraft 审阅段、Jellyfish consistency checker，分别借鉴证据报告、R1—R4审阅方向和人物主体检查；不复制固定评分、工具权限或把人物检查等同于全能视频审核。来源与验证记录见[本轮足迹](devlog/2026-10-20-storyboard-review-01a151.md)。未验证真实模型效果。

## 型号与思考等级

输入区提交按钮旁仅保留“模型、思考”两个紧凑选项。型号来自已保存的配置；添加配置时可手填服务支持的任意型号，当前不自动联网拉取全部型号。API地址和密钥仍在折叠配置区，新增“接口规则”用于明确参数协议，不凭型号字符串猜供应商。

- 通用兼容：旧配置默认选此规则，只提供“默认”，保持旧请求参数。
- 兼容思考参数：默认提供低/中/高，发送reasoning_effort及max_completion_tokens。具体型号必须支持这些字段；可通过API的reasoning_levels声明更窄或其他受控档位，不能据此宣称模型已验证。
- DeepSeek：提供默认、关闭、低、高、最高；按官方thinking与reasoning_effort转换。“默认”不发送显式思考字段，“关闭”发送disabled。

模型配置新增字段均向后兼容，可复用现有JSONB，无需继续升级业务库。旧配置如需要思考选项，应新建选择对应接口规则的配置；不改历史配置。页面会记住本标签页的等级选择；网络结果待核对时锁定本次型号/等级，避免恢复时换参数再调用。后台和历史manifest记录实际发送参数，不回显密钥或思考过程。API请求可带reasoning_effort，省略或default保留旧幂等身份；改变等级需新请求键。

这段只接入分镜与文字审核；旧编剧模型入口尚未统一，真实模型兼容与质量仍需显式验证。来源和测试记录见[本轮足迹](devlog/2026-10-20-model-parameters-01a151.md)。

## 首轮真实模型效果记录

2026-10-20用实际DeepSeek Flash完成9次分镜生成与7次文字审核；结构成功不等于专业质量合格，审核发现噪声与截断。本轮修复合法节拍时长证据被拒的问题；未修改业务库。完整结果及未执行对照见[真实评测报告](qa/storyboard-real-20261020-01a151/report.md)，不能以先前Mock测试替代该结果，也不能以这次短案例代替长期稳定性验证。

## 审核质量更新（2026-10-22）

审核规则升级1.1.0：允许合理时间余量；不重复报告已披露且无冲突的构图假设；合并同一根因，保留独立重要问题。旧1.0.0规则和历史报告保持原样。

模型因长度上限结束时返回output_truncated，界面提示降低思考档位或在模型支持范围内调整输出预算，再由用户手动重试；不会把残余JSON当完整报告，也不自动再次收费。

四个短案例使用low及12000输出预算返回有效报告，两个合理方案未误报，两个植入错误被定位。可以作为短分镜的初始选项，但未做同输入档位对照，未改变产品默认档位/预算；详见[控制组结果与局限](qa/review-controls-20261022-01a151/report.md)。
