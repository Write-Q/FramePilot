> 本文记录自由编剧流程的实现，整理于 2026-09-24。已验证流程分支和停止条件，尚未用标注数据证明真实编剧或审核质量。

## 标题不是剧本，先审核会发生什么

测试时，如果输入只有“哈基米文明的故事”，约束是“喜剧，30秒”，系统直接审核这几个字，就会指出没有人物、场景、动作和冲突。

单看审核结论，这不难理解；但放到自由创作模式里，交互不合理。用户已经授权 AI 构思故事，却又被要求先把故事写完整。问题出在流程顺序：缺少先构思、再成稿的步骤。

于是自由编剧改为：

```text
plan 构思 → compose 写稿 → review 审核 → decide 判断
                                           ├─ revise 修订 → review
                                           └─ human 等待用户
```

## 自主发挥需要明确材料和边界

`original_story` 是用户最初的输入；`outline` 是 AI 构思的故事骨架；`draft` 是当前完整正文。它们分开保存，让后续审核和用户复盘能看出哪些内容原本就有，哪些是后来生成的。

普通创作空白，例如一个喜剧误会怎样发生，可以由自由编剧补全。但用户规定了时长、结局或不可改变的事实，AI 不能把越过这些要求当成创作自由。

当前审核会标记 `needs_user`，表示是否需要用户参与决策。模型认为可以在约束内解决的问题，可以进入自动修订；必须突破授权边界的问题则应暂停。这个判断仍依赖模型，程序不能保证它每次理解都正确。

## 自动循环如何停止

| 情况 | 当前处理 |
| --- | --- |
| 没有报告待处理问题 | 等待用户确认 |
| 有问题需要用户决策 | 暂停并展示问题 |
| 累计完成三次修订 | 停止自动改稿，保留结果 |
| 剩余额度不足以修订并复审 | 暂停，不发起半套操作 |
| 连续两轮仍保留全部旧问题编号 | 标记无进展并暂停 |

问题编号由类别和逐字引用生成。同样的问题换了证据文字，可能得到新编号。因此，无进展检测只是一个保守的防循环规则，不是对内容改善程度的完整评估。

用户补充新方向后，可以在剩余额度内继续。停滞计数可以重置，累计调用数和修订次数不会重置。

## “审核通过”也不自动出片

当前流程没有接入视频生成平台。即使审核没有报告问题，也会停下来等用户确认。需要分清“模型没有发现问题”“用户认可当前稿”和“已经生成视频”是三个不同的状态。

同样，原稿直接制作入口只保存并导出原稿，不调用模型，也不代表已经把任务送到了视频服务。

## 这轮验证到哪里

测试覆盖了标题先构思成稿、重复问题停止、可以修复的问题自动进入下一轮、需要用户的问题暂停，以及三轮上限。模型替身能让这些场景稳定出现，适合验证程序路由。

实际创作效果还需要真实案例：短片时长是否合理，笑点是否成立，修订有没有引入新的矛盾。未来接入 RAG，也要先回答检索材料能否帮助这些问题，而不是把检索接上就宣布质量提升。
