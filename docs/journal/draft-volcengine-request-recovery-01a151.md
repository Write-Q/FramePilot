title: 接入视频生成服务时，断线恢复为什么不能等于重新生成
draft: true
---

FramePilot这次决定使用火山方舟，图片走Seedream，视频走Seedance。供应商由我选择，协议适配和测试由Coding Agent辅助实现；真实账户试片还没开始。

接入后最值得记住的事情，是一次请求可能在网页收到答复以前，就已经到达供应商。网页报错，并不能证明生成没有发生。如果直接重新提交，可能制造第二笔费用。

项目因此保留了两个不同阶段：先提交生成，拿到外部任务编号并保存；以后只查询这个编号。提交超时则保留“结果未知”，交给人核对，不自动再生成。下载到的文件也要经过实际解码，才能成为可选素材。

这次浏览器测试故意让服务器接收到请求后丢掉网页响应。恢复时再次发送原来的参数和幂等编号，最终模拟供应商只收到一次视频生成。这证明恢复机制可用，还不能证明真实平台的画质、收费和账户权限。

代码审查又发现了界面上的一个细节：找回任务后，“同意这一次生成”的勾选也必须清除。否则，技术上虽然没有重复恢复同一请求，用户下一次点击却可能沿用上次确认，创建一个新的请求。修复后增加了先失败、再通过的浏览器用例。

我的收获是，AI应用开发除了让模型返回结果，还需要把“这次到底有没有执行”“现在恢复的是哪一次”“下一次是否重新确认”表达清楚。模型接入的边界，往往藏在这些普通的状态和按钮中。
