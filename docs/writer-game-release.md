# 编剧工作台与文字游戏整合版（2026-10-15）

本版按本地单用户使用范围整理。功能基线为 `7efe7b2`；编剧工作台和文字游戏已在同一个 FastAPI 应用中提供，既有数据保持各自的业务边界。本说明不是视频生成或 DomainVideo 升级的完成声明。

后续补验：Docker 已在用户授权后恢复，完整 PostgreSQL 回归及编剧体验修复已通过，详见 [2026-10-15 修复与补验报告](qa/writer-ux-fix-2026-10-15-01a138.md)。下方“本轮验证状态”保留首次收尾时的历史结果。

## 可以使用的流程

| 模块 | 入口 | 当前交付 |
| --- | --- | --- |
| 编剧工作台 | `/`、`/api/projects` | 协作方向选择、自由创作、审核及逐条决策、仅澄清、人工确认、版本差异、Markdown 导出、失败手动重试 |
| 文字游戏 | `/play`、`/api/game` | 自填或 AI 候选背景、行动与程序判定、死亡模式、分支回溯、持久化存档、路线 Markdown 导出、可选插图网关 |
| 公共底座 | PostgreSQL、文本 Provider | 同应用运行，分别保存编剧项目与游戏存档，使用独立的业务调用预算；主应用管理文本 Provider 生命周期 |

页面导航可在编剧与游戏之间切换。游戏回合不会自动成为编剧正式版本；路线导出不等于剧本审核通过，也不等于正式资产入库。当前如需改编，可先导出路线 Markdown，再由用户检查并把所需正文作为编剧输入；这是人工交接，不是自动改编功能。

## 如何运行与验收

安装、数据库配置和启动命令见 [README](../README.md)。已有数据库升级前先备份，再显式执行 `python -m scripts.init_db`；本次收尾核对没有对业务数据库执行迁移。

1. 启动后访问 `/`，协作模式输入一个标题，确认先显示候选方向，选择后才写稿。
2. 对完整剧本执行审核，分别检查采用建议、用户替代方案、保留理由；仅澄清时正文和版本应保持不变。
3. 查看历史版本、差异与导出；原稿直接制作模式应保持零模型调用，并标识未经审核。
4. 通过导航进入 `/play`，确认背景后提交行动，检查存档、死亡模式和历史分支；回溯不覆盖旧路线。
5. 导出游戏路线，再回到编剧工作台，确认游戏操作没有修改旧编剧项目。

上述模型交互手工验收需要有效配置并可能产生费用，本轮没有执行。自动化测试使用模型替身，不代表真实编剧、审核或画面质量已经验证。
