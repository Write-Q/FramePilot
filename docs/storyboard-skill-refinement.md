# 分镜规则优化：第一步

本轮只将资料库中的专业方法适配到现有K001—K003，当前版本为1.1.0。生成仍为一次文本模型请求；独立审核、真实模型质量评估和图像生成属于后续步骤。数据库、输出schema和页面无需迁移或改版。

## 实际补充

| 模块 | 本轮改动 | 固定来源定位 |
| --- | --- | --- |
| K001规划 | 场次/节拍顺序、每镜信息目的、原话与声音归属、长台词连续、时长余量、数量不足时保留缺口 | Toonflow storyboardTable：拆分方法/写入后审阅；shotCraft：镜头语法/台词与时长 |
| K002自检 | 每场位置基准与变化点、持物手/数量/服装/伤势、特写与画外人物、有意跨轴、换场与反射 | Toonflow shotCraft：空间与连续性；storyboardTeam连续性知识与reviewer |
| K003静态帧 | 区分已成立静态状态与连续动作起始态、起幅/落幅、关键物件与故事内文字、相邻镜上下文 | Toonflow imagePromptCraft：从分镜到单帧/字段映射/质量与忠实性检查；Jellyfish帧模板的_FRAME_FOCUS等 |

来源确切仓库/提交/路径/章节在 `app/production/skills/registry.json`，对应资料库的[项目索引](knowledge/aigc-video/project-prompt-inventory.json)。本轮没有重复镜像外部正文。

未照搬外部15秒片段、固定字速、品牌专用JSON/负面参数、素材编号、画布协议或工具权限。提示词只消费本项目既有字段，问题仍落在continuity_notes/creative_notes。

## 两个重要边界

- 首帧不能提前出现后续完成态，但原文“已经停步仰望”应保留，不退回“即将抬头”。
- 固定镜头数不足以覆盖必要场次时，不伪造空间合并、不删结尾或谎称全覆盖：保留未分配场次、标出缺口并建议人工调整镜头数。本轮没有新增自动镜头数或不适配任务类型，用户仍需修改要求重生成。

这些是模型应遵循的规则，不代表程序已经能证明模型遵循。程序规则版本维持storyboard-checks-1.0.0，仍提供有限warning；语义审核未在本轮新增。

## 版本与追溯

- 活跃规则1.1.0及其内容哈希由registry登记，组包流程为storyboard-planner-1.1.0。
- 原1.0.0规则与manifest保留在 `app/production/skills/archive/1.0.0/`，可核对既有运行清单的哈希。归档只保留旧规则本体，不提供旧生成器回滚执行接口。
- 每次新运行保存id/version/sha256/sources与source_locators；历史记录不改写。
- 更新后重启应用以加载新版组包代码，不能只替换规则文件并继续使用内存中的旧生成器。
- 规则缺失、文本与登记哈希不同、版本标题不符或元数据错误时，在预约和请求模型前返回503。修复规则后才能再发新请求；已有幂等结果和历史仍可读取。

三份规则正文合计由2154字符调整为4266字符，JSON Schema与本次剧本另计。字符数不是token数，不代表费用翻倍；本轮未测真实用量、时延或效果。

## 验证与下一步

`tests/fixtures/storyboard_skill_cases_1.1.0.json`定义9类真实模型/人工验收条件：交接、长对白反应镜、已成立静态状态、运镜起落幅、无声短信、数量不足、原稿冲突、有意跨轴、反射和画外人物。全部`model_evaluation=not_run`；静态审阅仅核对这些预期在规则中有明确表达，不给模型打“通过”分。

自动回归验证版本来源、内容完整性、旧哈希兼容、失败不预约/不调用、生成记录、编辑/确认与浏览器。它不能替代上述专业效果验收。

本轮到此为止。下一步另行实现独立文字分镜审核，再在固定模型与案例上开展对比；不提前混入本轮调用。
