# 故事创作最小闭环实施记录

目标：替换旧模拟视频接口，落地 DeepSeek + LangGraph 故事提取、审核、有限修订和人工确认。

## 本轮设计选择

- 单机单用户、一个服务进程；SQLite 分别保存业务快照/版本/调用账本及 LangGraph 检查点。后续再迁移 PostgreSQL。
- 三种模式：faithful / collaborative / free。忠于原稿和协作创作有未解决问题时暂停，用户明确提出修订要求后只执行一次修订再审核；自由发挥可在允许范围内自动修订。
- 审核发现约束冲突或需要用户决策时，所有模式均暂停。自动处理权限由程序判断，不依赖提示词一句承诺。
- 一个项目累计最多修订 3 轮、默认最多 10 次模型请求；恢复不会重置。首次提取与审核不计修订轮次。失败请求计数，无自动网络重试。
- 十个创作维度均有内容、来源和原文依据；未知可明确留空。审核证据必须引用原稿、当前草稿或用户约束的实际片段，否则失败且不视为通过。
- 人工恢复必须携带当前版本和 interrupt_id；确认存在疑点的版本须显式接受问题编号。需要澄清和约束类问题不能直接忽略。
- 本轮不实现质量分数、无进展检测、视频生成、RAG、MCP、多人权限。调用上限不是金额预算，不宣称能限制实际费用。

## 文件职责

- app/domain.py：业务输入、输出与状态约定。
- app/provider.py、app/prompts.py：DeepSeek JSON 调用与版本化提示。
- app/workflow.py：LangGraph 节点、条件路由、interrupt。
- app/storage.py、app/service.py：持久化、调用配额、版本和恢复防重。
- app/main.py：本地 FastAPI、离线 Swagger 与简单操作页面。
- tests/：确定性模型替身验证行为，不将它当真实模型质量评测。

## 验收

1. 无问题故事等待确认；确认不触发新模型请求。
2. 协作/忠实模式有问题立即暂停；自由模式有限修订。
3. 用户恢复和进程重启保留版本、累计轮次及请求数。
4. 错误/过期恢复、假证据、无效 JSON、预算耗尽均不会误报成功。
5. 人工问题接受规则可验证；原稿永远保留。
6. 使用一个短故事执行真实 DeepSeek 冒烟测试，不据此报告准确率。
7. 阶段结束整理博客草稿，等待用户审阅，不自动上线。
