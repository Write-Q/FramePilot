# 编剧模块使用与验收（2026-09-22）

## 当前入口

- 协作创作：提取并判断输入完整度。标题/片段会生成 2–3 个候选方向，等待用户选择并补充要求；完整剧本直接审核。选择后编写剧本，审核后等待用户决策。
- 自由编剧：构思 → 编写 → 审核 → 有限自动修订。普通创作空白由模型补全，明确约束冲突或授权边界需用户处理。
- 原稿直接制作：不调用模型、不审核、不改写，保留原稿并提供 Markdown 交接导出。视频平台未接入，不能直接出片。旧 faithful 项目兼容读取及恢复，不再作为页面的新建模式。

## 协作审核后的操作

每条问题可选择暂不处理、采用 AI 修改建议、用我的方案替换、保留原设定并解释原因。原建议从服务器读取，客户端只传问题编号、选择和用户文字。建议编号绑定当前版本和暂停编号，旧请求不能重复执行。

“按所选方案修改并审核”才实际改稿：保存新版正文、更新概括卡片、重新审核。用户的替代文字不覆盖原建议记录；两者一起进入历史决策，便于追溯。模型被明确要求仅修改授权内容，语义层面的修改边界仍需用户检查，不宣称程序可证明模型完全遵守。

未选择的问题不会自动视为接受。逐条处理后模型未再次报告的未处理项，以“未处理项，依据来自版本 N”保留；用户可进一步处理或接受其中的建议性问题。

原有“确认时接受此问题并保留现状”复选框只表示接受现状，不执行改稿。与采用修改建议是两种不同操作。存在必须澄清/约束问题时不能直接确认。

## 仅澄清

填写背景解释或逐条保留理由，点击“仅澄清并复审，不改稿”。只更新反馈/决策历史并审核，正文、卡片、版本和修订次数保持不变，消耗一次模型请求。

仅澄清期间即使处于自由模式也不自动转入修订。若还有问题，交还用户；需要修改卡片中的事实或正文时使用修改操作。不能把采用/替换建议混进仅澄清请求。

## 版本与交接

原始输入永久保留。可查看故事骨架、当前剧本、历史版本、相邻正文版本的差异（+ 新增，- 删除）、历史决策。协作选择方向之前的输入作为 V1，首个生成剧本为 V2；自由编剧的首稿为 V1，最初输入另存。

导出包含当前稿、最初输入、用户要求、未解决问题和决策记录。导出不代表审核通过；直通原稿明确标记未经审核。没有一键回滚，旧版本可查看和导出后另行创建项目。

## 失败与边界

失败状态可手动重试失败节点，项目编号和累计调用额度不变；进行中的任务或非失败状态不能重试。模型输出/引用校验仍生效。人工暂停可重启后恢复。服务进程异常退出时的任务恢复、执行取消和后台可靠队列不属于当前单机编剧模块的完成范围。

最多 3 次正文修订、10 次模型调用；澄清也占用调用额度。自由模式连续两轮同类型同证据问题未消除时暂停，这不是完整语义进展评估。

## 验证证据与未完成的质量验证

自动化测试覆盖候选方向选择、重启恢复、过期请求拒绝、采用/替换建议、未处理项保留、仅澄清不改稿、模式权限、调用预算、直通零调用、差异/导出与失败重试。浏览器通过本地测试模型验证整条交互，没有外发用户故事。

真实 DeepSeek 新版联调和标注案例质量评测尚未完成，不能用单元测试通过推断编剧或审核准确率。RAG、视频平台和任务队列是后续独立模块。2026-09-23 已迁移至 PostgreSQL，详见 postgresql.md；创作交互保持不变。

## 手工验收案例

1. 协作输入“猫文明”，约束“30秒喜剧”：应看到候选方向，选择前不写完整正文。
2. 完整钥匙矛盾故事：采用一条建议、替换另一条，提交后检查差异和决策记录。
3. 对疑似伏笔填写保留理由并仅澄清：正文和版本保持不变。
4. 自由输入标题：应自主构思、写作并审核；达到停止条件后返回明确状态。
5. 直通入口：调用数为 0，导出原稿，明确未接视频平台。
