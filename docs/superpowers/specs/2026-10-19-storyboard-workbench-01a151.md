# 分镜工作台第一版设计

用户已确认目标：已确认剧本 → AI 文字分镜 → 人工修改 → 新版本 → 检查 → 确认保存。沿用旧默认章节交接，不扩展多章节 UI。

## 数据与流程

生成输入：project_id、source_version、确切文本 profile_id/version、幂等键、目标镜头数（1—30）、画幅、风格与创作补充。补充不能覆盖已确认剧情。完整来源/约束/故事卡片进入模型上下文；资料库规则编写为版本化的本项目 Skill，随提示词 schema 传入。

一次显式点击最多一次 Chat Completions 请求，无隐式修复/重试。输出 Pydantic 校验、逐字来源校验、镜头数量和指定画幅校验，绑定配置由服务写入而非信任模型。失败不创建分镜。生成后再次锁定项目检查来源当前且确认，来源变化则保留失败记录而不落过期结果。

专用 fp_storyboard_runs 记录：项目、幂等键/请求摘要、来源剧本版本 FK、文本配置版本 FK、输入和 Skill 清单、状态（running/succeeded/failed/abandoned）、错误码、用量、分镜版本 FK、时间。项目同一时刻一个运行，最多十次分镜请求；与编剧十次额度分别计数并在页面说明。网络开始前提交预约，网络期间无数据库锁。相同幂等键只返回原记录，不重发；换内容复用键报冲突。进程退出留下 running；用户可显式标记中断（不等于取消外部请求），旧调用返回不得再保存结果。

## 专业契约

沿用已有场次、镜头、节拍、构图、方向、状态、对白、声音、静态帧与运动字段；补充结构化对白片段（说话人、原话）、画面人物、创作补充说明。原字符串 dialogue 保留兼容。首/关键/尾帧是计划文字，不承诺模型输入支持。无需更新已存分镜 JSON：新增字段有默认值。

程序检查返回规则版本和逐镜警告：必需制作描述未填、场次未覆盖、对白时长启发式、相邻镜头计划状态不连续、动作过载。仅提示，语义/空间/审美不能由这些检查证明；人工确认界面要求阅读提示。Skill K001 规划、K002 空间与连续性自检、K003 静态帧设计以一次调用组合；不是三次模型审核，也不是可独立执行 Agent。

## 界面

独立 /storyboard 页面沿用纸色/墨绿，面向制片的镜头清单与右侧编辑表单。可从编剧页带项目编号跳转；载入剧本状态、配置、新建配置、生成、恢复运行记录、选择分镜系列/历史、镜头编辑/增加/删除/重排、保存新版本、查看规则提示和确认。场次在系列内固定；要调整场次则重新生成新系列。历史只读，旧版确认不继承，新版与来源状态明确展示。DOM 使用 textContent，用户输入不拼接 HTML。

## 验证与边界

httpx MockTransport 验证真实适配器序列化、密钥隐私、错误/截断、无自动重试。临时 PostgreSQL 测试幂等、隔离、原子落库、源变化、运行中断、固定配置。浏览器替身模型回归生成/编辑/版本/确认、移动端溢出、错误保护。测试不访问真实付费模型，不升级业务库；真实模型质量待用户配置后验证。
