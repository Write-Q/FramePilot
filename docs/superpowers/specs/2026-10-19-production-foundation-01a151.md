# 第二版制作底座：首段设计

用户已同意开始开发。依据本次讨论，第二版分为镜头制作与后期剪辑两块，共用模型配置、媒体和任务设施。首段交付模型配置 API 与手工分镜编辑/确认 API；后续自动规划与付费媒体生成使用相同边界接入。

## 首段可验收行为

1. 创建、读取和按版本更新模型配置。用途包括 text/image/video/review/asr/tts；配置含名称、适配器、base_url、model、环境变量密钥引用、超时和受限生成参数。密钥实际值不经本接口存储、返回或测试。配置版本不可变，更新携带预期版本，过期返回409。预留图像/视频适配器选择，未实现适配器明确标注不可执行。
2. 从旧编剧入口的已确认正文版本创建分镜。要求正文版本仍为当前已确认版本，拒绝原稿直送和未确认稿。只读使用既有兼容桥对应的领域剧本版本，不改写编剧状态。
3. 每次保存分镜创建新的不可变版本；包含场戏及镜头、原文引用、叙事目的、动作、景别、机位、生成运镜、时长、声音、起止状态。镜头稳定键与版本内数据库ID分离，支持重排、增删、拆分与用户编辑。原文引用须逐字存在，时长必须正数，镜头编号唯一，场戏引用必须有效。
4. 分镜版本引用可选的确切模型配置版本；只保存配置身份/版本，不含密钥。确认通过独立追加记录表达，确认后编辑生成新版本，新版本重新确认；不自动调用生图、视频或审核模型。
5. 列表、读取、编辑和确认均可通过本机 Swagger 使用。首段不新建前端界面、不增加供应商凭据、不执行付费调用，也不将手工分镜声明为 AI 生成。

## 数据与执行边界

继续使用 PostgreSQL、SQLAlchemy 和显式 Alembic 迁移。复用 breakdown_versions/scenes/storyboard_versions/shots；首段固定每次初始分镜创建的场戏拆解，修订时引用同一拆解，场戏重拆属于新建制作分镜。新增全局模型配置身份/不可变版本和分镜确认记录表。项目行锁串行化分镜版本分配，配置行锁串行化配置更新。确认引用具体版本，不赋予未来付费生成授权。

配置用途和能力是人工声明，不能表示真实模型能力已经验证。适配器目录首段只提供契约/可用状态，不猜测尚未确定的视频供应商协议。旧编剧 DeepSeek 与游戏网关保持现状，迁移到通用配置在后续明确接入阶段完成。

## 验证

先写失败测试，再实现。覆盖参数校验、秘密字段拒绝、跨用途绑定、失效版本冲突、未确认剧本拒绝、来源引用校验、不可变分镜历史、项目隔离、确认绑定版本以及应用入口集成。真实 PostgreSQL 测试只使用随机临时库，业务库不升级。本轮使用模型替身回归，不证明真实视频质量。当前工作区已有其他任务修改，采用新增文件及最小入口修改，不批量暂存或提交。
