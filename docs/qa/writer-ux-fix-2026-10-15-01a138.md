用户已授权恢复 Docker，并要求修复上一轮报告中的三个体验问题。产品改动仅涉及 `workbench.js` 和 `workbench.css`，没有改变编剧权限、调用预算或模型提示词。

## 修复结果

| 原问题 | 当前行为 | 验证 |
| --- | --- | --- |
| 新项目残留上一项目要求 | 未提交意见按项目隔离，回到旧项目可恢复自己的输入 | 真实 PostgreSQL + 浏览器回归通过 |

草稿不是正式提交：成功提交后清除；版本或暂停编号变化时不沿用。特别补测了“仅澄清不增加正文版本，但会产生新暂停点”的情况，确认已提交意见不会重新出现。会话存储不可用时退回当前页面内存；不承诺跨标签页、跨设备或浏览器清理后的恢复。

## 验证证据

- Docker 引擎恢复，`docker compose up -d --wait db` 返回 PostgreSQL 容器健康。用户授权后备份两个运行时套接字目录，没有删除或重置数据库卷。
- 原有完整隔离 PostgreSQL 回归：79 passed。
- 修改前先加入浏览器断言：3 组明确失败（跨项目意见、刷新方案、提示可见性）、1 组成功提交后清理测试通过，随后才修改产品代码。
- 修改后完整回归：**80 passed、0 skipped**，耗时 33.46 秒，1 条既有第三方弃用警告。其中新增的 1 项 Python 用例内包含最初 4 组浏览器回归。
- 审查后增加“同版本、不同暂停点”边界，再定向运行浏览器用例：**1 passed**，内部 5 组浏览器测试全部通过，耗时 7.16 秒。
- Node 展示转换测试：**6 passed**。`node --check app/static/workbench.js` 和 `git diff --check` 通过。
- 只读代码审查未发现必须修复的问题。建议的其他更广边界（多问题组合、完整方向选择草稿、网络中断）尚未逐一加入浏览器回归，不将其描述为全部覆盖。
- 所有新验证使用固定模型替身，没有新产生付费文本/图片请求；上述结论不代表真实模型写作质量提升。

## 运行回归

浏览器用例位于 `tests/test_writer_browser.py` 与 `tests/writer-ux.test.cjs`；沿用已有 PostgreSQL fixture，每次创建随机数据库并清理自己的库。

Node/Playwright/Chromium 是可选测试依赖。安装方式见 README；设置 `NODE_PATH` 后运行 `python -m scripts.test_local` 即可包含浏览器回归。没有浏览器依赖时会显式跳过此项，不应把跳过计为通过。可设置 `FRAMEPILOT_CHROME` 指定已有 Chromium，设置 `FRAMEPILOT_UI_ARTIFACTS` 保存校验提示截图。
