# 编剧稳定性优化与复测

已实现有限引用纠正、修订差异上下文和候选稿恢复保护。相同协议的6轮真实模型复测完成确认5/6，前批为2/6；这是小样本观察，不能推导生产成功率，也不能单独归因为某一项改动。

## 实现

- `app/workflow.py`：理解卡引用错误采用独立`repair_card`调用，仅返回卡片，正文由程序保留；引用依旧严格逐字校验。每次自动流程最多纠正一次，人工重试另外计费，统一受项目10次调用上限约束。网络或结构错误不触发证据纠正。
- 候选生成与采用拆为检查点节点，未校验通过不更新正式正文/版本。纠正失败后重建服务再重试，也只继续卡片纠正，不重新生成候选正文。采用后清空候选。
- `app/revision_context.py`与状态`previous_draft`：程序计算字符变更，向复审提供上一稿及变化。仅澄清后仍保留比较基线，不自动删除语义问题或绕过确认权限。
- `app/prompts.py`：版本`story-v6`，明确引用可短于总结、不可拼接；修改范围必须核对上一稿与程序差异，已有句子不能误说为新增。
- `app/service.py`：错误提示区分新稿未采用与正文已保存但审核失败，复用已有重试入口。
- 证据失败调用记为`invalid_evidence`并保留已返回tokens；避免把“模型返回JSON”记成业务校验通过。
