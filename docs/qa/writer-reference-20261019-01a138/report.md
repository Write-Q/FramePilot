# 来源编号与结构纠正：实现及新题材试用

已完成两项优化：模型从当前材料目录选择来源编号，程序核对来源后回填原文；字段或完整JSON输出错误最多自动纠正一次。120项回归通过。悬疑、喜剧、科幻各两轮真实流程均完成，但仍发现两次修改范围语义误报，其中一次需要澄清。流程可用不等于剧本质量合格。

## 实现与恢复边界

- `app/evidence_refs.py`按独立原稿、要求、反馈及审核正文生成连续原文片段。DeepSeek只输出`evidence_ref`，不自由抄写`evidence`/`quote`。编号不存在、来源不匹配、混入自由引用均拒绝；AI建议/未知项引用为空。回填后仍经现有Pydantic及原文校验。
- 目录、wire schema及原始引用编号只存在于模型调用边界；API快照、旧项目、版本和导出仍保留原有原文引用结构。其他Provider默认继续原契约，声明`evidence_references=True`时接入新协议。
- 大量短句时合并相邻连续片段，不跨材料、不改标点，单片段不超过1000字符。最大短句用例由19,500项/2,299,575字符降至78项/47,844字符；这是一项极端用例测量，不是所有请求的固定目录上限。
- `StructuredOutputError`区分可纠正的JSON/字段错误与网络、HTTP、截断、过滤。可纠正错误带具体字段路径重新请求一次；失败调用保留已知tokens，仍累计计入项目上限。引用和结构纠正共用同一轮自动纠正机会，不能叠加第三次请求。
- 正文有效且只有卡片错误时保留候选，独立`accept`节点只纠正卡片。自动纠正后的第二份正文若仅卡片错误，也保存该候选并暂停；显式人工retry才解除暂停进入卡片纠正，重启后不重新生成正文、不重置额度。
- 提示词版本`story-v7`。编号真实存在只证明出处真实，不保证总结、剧情推断或建议受到该片段充分支持。

## 历史坏卡片回放

另取预先确定的三份保存输出：写稿拼接引用、卡片多余占位字段、改稿引用转述。每份仅一次真实`repair_card`请求，使用当前来源目录与wire schema，**3/3**通过，未返回正文，共3次调用、12,191 tokens。

这是已知失败材料的局部纠正诊断，独立于六轮端到端样本；与此前自由抄写纠正2/3的结果可作观察，但材料选择与随机性不足以证明总体改进幅度。新增完整流程没有触发卡片纠正路径，其真实效果证据来自这组回放，持久化恢复功能证据来自回归测试。

## 人工阅读与仍存的问题

1. **修改范围误报仍有两次。** mystery-1误把“目标整行末尾”理解成目标行首句的末尾，形成constraint阻断；事实澄清后解除。mystery-2仍声称新增句另起一行，归为continuity且不阻断确认，所以没有触发本批澄清规则，误报随建议保留。两轮程序比较均证明仅追加指定句，全部换行数量和其余字符不变。来源正确不等于推断正确。
2. **悬疑可见线索不足。** mystery-1的站名/半个数字与封闭线路的关联没有清楚落实到画面，模型也保留了相关缺失建议。不能只靠“人物皱眉”让观众明白线索。
3. **喜剧因果与可拍性需人工把关。** comedy-1在20秒片段中表现接水、煮蛋到煮老，时间与可见性存在明显疑问；comedy-2把老式双铃闹钟当作带插头设备，模型已报告道具形态不连续。部分镜头动作密集，未实拍计时。审核建议中的机位/环境音补充是否必要，也应由创作者决定。
4. **科幻授权没有被当作常识违规。** 两份温室稿围绕明确允许的人工重力展开，没有将该设定本身报告为违约；不等于进行了科学正确性验证。

本轮不继续增加功能或无限调提示词。转入真实创作试用，由人审阅并决定改哪些建议，重点观察误报造成的额外操作、喜剧/悬疑因果和实际可拍时长。未完成长篇、盲评、多供应商、并发及真实模型浏览器点击验收；应用重建读取不等于执行中崩溃恢复。
