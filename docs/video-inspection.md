# 视频审核：技术证据与人工结论

本阶段针对成功视频的固定版本和checksum创建报告。技术信息、真实抽帧和人工结论分别留存，不替代分镜审核，也不自动修改剧本、重生成或选用素材。

## 使用范围

工作台对成功视频显式点击“检查视频”，生成技术报告和最多12张真实证据帧。点击证据可定位到视频中的对应时间。画面采样按实际解码帧均匀取样，报告保留时间戳；短片不足指定帧数时只返回真实存在的帧。

技术信息包含计划与实际时长、宽高、画幅差异等提醒。抽帧成功意味着文件经技术读取；不是人物一致、道具正确、口型同步或剧情忠实的证明。原始声音仍需试听，本阶段没有自动音频内容审核。

人工播放并核对后，可以记录问题时间段、严重程度、描述及整体备注，选择“已人工检查”或“需要修改”。这是明确的人工记录，不是AI自动通过或成片批准。原结论不被覆盖，新结论追加到历史；当前状态以最近记录展示。修改分镜或来源后报告过期，历史保留但不能继续写当前结论。

## 数据与执行

0010新增fp_video_inspections和fp_video_inspection_notes，不改写0009视频任务。应用不会自动迁移；启用前需备份并演练。创建报告和人工记录均使用幂等键，响应丢失可原键核对，不应新建重复意图。每视频最多10份报告，每报告最多50条人工记录。

接口位于 `/api/production/projects/{project}/storyboards/{board}/video-runs/{run}/inspections`：POST创建报告、GET历史；`/{report}/frames/{index}`读取真实帧；`/{report}/notes`追加人工记录。所有请求检查项目、视频、报告归属，不接受客户端提供本机文件路径。

视频及证据图片需要随数据库共同备份。文件checksum不符或缺失时不能对其冒称有效审核。子进程抽帧最多30秒，图片最大边640像素，帧数不超过12；未进行长时性能或操作系统级资源沙箱验证。

## 参考与边界

由本地资料库R011定位至[官方视频理解文档的时间戳与采样说明](https://ai.google.dev/gemini-api/docs/video-understanding)：采样率影响瞬时问题可见性，时间证据须与素材绑定。本项目使用本地PyAV采样，没有采用Gemini接口或声称模型能力已验证。

后续可增加疑点加密采样、可替换视觉模型审核与音画检查。本版没有联网自动内容审核，不以少量静态帧证明整段视频无缺陷。
