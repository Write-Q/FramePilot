# FramePilot 视频创作 Agent 项目计划书

岗位对齐优化版  版本 2.0  修订日期 2026年9月12日

本计划面向准备 Python AI 应用开发与 Agent 开发实习的计算机类本科生。项目以资料驱动的短视频创作为场景，训练模型接入、工具调用、检索、上下文管理、后端工程、可靠执行与效果评测。目标是完成可以运行、可以解释、可以独立修改的求职主项目，同时支持个人创作。

核心决策是保留视频主线，优先完成一条有事实依据、有人类审核、能处理失败的创作流程。岗位核对支持这条能力方向，但不构成全部招聘岗位的统一标准，也不保证录用。本文的功能、指标和工期均为建设目标，不是已完成成果。

## 本次优化改变什么

| 原计划重点 | 新版处理 | 目的 |
| --- | --- | --- |
| 16周完成全部L3能力 | 16周争取核心求职版，随后8周完善L3，另留4周缓冲 | 将独立学习和故障验证计入工期 |
| 视频题材保持开放 | 主验收用资料驱动短片，氛围创作保留为个人使用模式 | 使RAG和引用产生真实业务价值 |
| 最后集中完成评测 | 第一阶段留样例，Agent上线当周跑开发集 | 及时识别无效复杂度 |
| 主要列出技术名称 | 每项能力绑定代码、测试、日志和口述题 | 把覆盖转化为掌握证据 |
| 永久不使用ORM | 先手写SQL，后续按维护收益决定 | 保留学习目标，避免无依据的禁令 |
| 仅一家企业岗位为依据 | 增加BOSS公开摘要和企业官网实习岗位 | 分开核对技术方向与实际投递条件 |

## 方案选择

保留原版一次完成全部功能，容易推迟第一次完整交付；改做纯知识库，能减少视频成本，却削弱个人创作动机。本版选择分阶段完成视频Agent：核心版先形成求职证据，进阶版再证明复杂故障与并发条件下的正确性。

核心版不是最终目标缩水。原版的持久化恢复、并发预算、MCP、检索对照和故障矩阵全部保留到L3；每次投递只描述当时实际验收通过的能力。前端、供应商数量和视觉装饰服从主流程。

阅读顺序：先看岗位证据与能力矩阵，再看产品、架构和验收，最后按阶段开始。本文替代原版排期与优先级；原版中的有效安全、版本和预算约束继续保留。

## 小范围补充

用Dify或Coze二选一复现“检索资料并生成带引用脚本”的小流程，记录与代码方案的控制能力、调试方式和限制。预算为4～6小时，作为岗位认知练习，不迁移主系统、不维护第二套产品。[R4][R5]

## 完成的定义

每项交付必须同时回答：用户能做什么；哪个模块实现；怎样证明正确；本人能否独立修改。用“未开始、开发中、已验证”记录状态，禁止把依赖已安装或接口已接通直接写成能力已掌握。

# 三 产品范围与真实使用场景

项目定位为资料驱动且支持可恢复执行的短视频创作Agent。主用户是个人创作者；开发验收先支持20～30秒、3～5个镜头、一种画幅、一种字幕样式和一家视频供应商。账号题材仍可探索，播放量不作为软件通过条件。

## 两种使用模式

资料驱动模式是主验收场景：上传产品说明、公开知识材料或自有创作资料，提出受众与时长，生成有出处的脚本和分镜。需要区分事实陈述与创意表达；资料不足时追问、删除无依据事实或明确缺失。

自由创作模式用于氛围与故事探索，可以不检索。模型根据任务选择是否调用检索工具，不能为了展示RAG强制每条视频查资料。两种模式复用项目、镜头、审批、执行和资产管理。

## 用户主流程

创建项目并上传资料 → 澄清必要需求 → 检索和生成脚本 → 查看引用与编辑分镜 → 确认版本、范围和预算 → 后台生成与拼接 → 预览下载 → 按镜头提出修改 → 确认影响范围并生成新版本。

例如“根据这份说明做一条面向新手的20秒短片”，系统只能引用文档支持的产品事实。用户随后说“第三镜头更简洁，其他不变”，系统提出第三镜头的新版本及重新拼接计划；已批准且未受影响的片段保持不变。

## 最小交互界面

| 页面或区域 | 必须能完成的操作 |
| --- | --- |
| 项目与资料 | 新建、查看、导入、索引状态、删除；显示资料版本 |
| 对话与分镜 | 澄清需求、查看出处、修改镜头、查看待批准计划 |
| 执行与费用 | 显示当前步骤、已知费用或估算、未知结果、取消与重试范围 |
| 预览与版本 | 播放下载、比较版本、指定镜头修改、查看素材复用 |

允许合并页面为少数区域。使用React、TypeScript和Vite，先完成表单、状态与错误反馈；不做完整剪辑时间线、协作编辑、复杂仪表盘和自动发布。

## 明确的边界

镜头重生成不是像素级编辑；角色与参考图不能保证绝对一致。字幕、转码、拼接由确定性媒体程序执行。已提交任务能否取消及取消收费以供应商为准。视觉模型辅助理解参考图可在L3后增加，不能据接入视频API声称自研视频模型。

# 四 技术选择与系统职责

采用模块化单体后端和独立worker。客户端只经授权接口访问业务资源；PostgreSQL保存业务事实，队列负责工作分发，LangGraph负责受控决策与对话状态。先让依赖关系清楚，再考虑抽成可复用组件。

| 层次 | 选择 | 约束与用途 |
| --- | --- | --- |
| API | FastAPI、Pydantic、HTTPX | 参数、认证上下文、超时、连接复用；长任务返回ID |
| 模型与Agent | 官方SDK、必要LangChain组件、LangGraph | 先手写循环；业务权限不能依赖Prompt |
| 数据 | PostgreSQL、psycopg、连接池、pgvector | 参数化SQL、事务、唯一约束、编号迁移 |
| 后台 | Celery、Redis | 短轮询任务、退避、并发限制；不长期睡眠占worker |
| 资料检索 | 文本解析、Embedding、中文分词、BM25 | 向量基线先行，融合与重排以实测决定 |
| 资产 | 本地受控目录，交付时接对象存储适配器 | 数据库存元数据；私有读取、来源、规格和校验值 |
| 媒体与界面 | FFmpeg、ffprobe；React、TypeScript、SSE | 参数化媒体命令；重连后查数据库真实状态 |
| 质量 | pytest、结构化日志、LangSmith、Compose、CI | 统一关联ID；追踪可关闭，业务记录不依赖第三方 |

## 数据模型按需求增长

先建立users、projects、shots和shot_versions。接入执行后增加plans、approvals、runs、operations、assets及render_manifests；再增加documents、chunks、series_settings、context_summaries、usage_records和budget_reservations。L3独立抽出outbox_events和run_events。

核心约束包括项目归属、镜头与版本组合唯一、操作幂等键唯一、批准绑定计划版本、成片清单引用确切素材版本。保存当前修订号，以乐观并发控制拒绝基于旧版本的修改。索引选择用实际查询和EXPLAIN说明。

## SQL与ORM

前期用手写SQL学习事务、连接池与索引；通过repository接口隔离数据访问。若后期CRUD维护成本明显增加，可评估SQLAlchemy等方案并记录取舍。不得同时维护两套数据访问主线，也不为招聘关键词重写已验证模块。

Windows用于编辑，集成运行使用WSL2或Linux容器。项目必须使用Python虚拟环境；依赖在首个可运行版本锁定。生产密钥与配置外置，真实模型、视频供应商及准确版本在接入测试后选择，不能由计划书虚构可用性或单价。

# 五 Agent与检索的实现要求

## 先理解循环再使用框架

最小循环需要展示模型请求工具、参数校验、执行、按调用ID回传结果、模型根据反馈继续或结束。之后迁入LangGraph，保持同一套业务工具和测试，说明框架带来的状态保存与中断能力。

模型可决定是否追问、如何检索、读取何种已授权设定以及如何提出修改方案。批准、权限、预算预留、状态转换与素材发布由后端校验。分别限制模型轮数、工具数、token、总时间及连续无进展次数；触发限制时保存状态并暂停。

每个工具说明输入输出schema、错误类型、副作用和可重试条件。初期提供search_materials、get_series_settings、save_draft_plan和get_run_status；付费执行必须经过业务审批接口。最终答复声称完成前，要检查运行终态和产物是否存在。

## RAG必须有可检查的事实任务

首批准备20～30份短资料，覆盖产品说明、公开科普和自有系列设定，注明权限与来源。先支持TXT、Markdown和文本PDF；保留原文、文档版本、章节或页码。分块参数与Embedding版本进入索引元数据。

建立有标注相关片段的查询集，比较向量检索、中文分词后的BM25与融合排序。相同资料、任务、候选数量和生成设置下对比；重排序只有在收益大于额外成本时加入。不能假设默认全文检索自动解决中文分词。

检索必须限定项目和用户权限。资料更新时建立新索引版本；旧脚本保留引用快照。删除后禁止新查询访问并清理索引与缓存；已生成内容的保留策略要向用户说明，不能声称删除索引自动删除历史成片。

## 上下文与记忆

上下文按任务事实、确认设定、摘要、近期消息和检索片段装配。预算、批准、运行ID和版本从数据库读取；摘要不得覆盖权威事实。达到token阈值后压缩历史，记录覆盖边界并保留原始对话。

长期记忆仅保存用户确认的设定，支持更新、撤销和冲突消解。用长对话、反复改口、压缩前后测试验证。MCP阶段把两个只读工具暴露给真实客户端，测试发现、调用、超时、schema错误和越权拒绝；工具协议不替代服务端权限。

# 六 可靠执行与业务状态

付费调用前就必须有操作记录和批准校验，不能把安全边界全部延期到L3。核心版可以限制同一项目单次执行；L3才扩大并发并验证跨worker故障。这是实现深度分阶段，不是降低付费操作的底线。

## 从操作记录开始

在数据库事务中保存操作、批准版本、预算预留和待派发状态。核心版以持久operations记录扫描未派发工作并去重；它承担最小持久工作日志职责。L3将派发事件明确分离为outbox，仍要求消息重复不产生新的业务操作。

外部提交前保存请求标识。供应商支持幂等键时始终复用；确认成功后保存外部任务ID。提交超时而结果无法确认时进入UNKNOWN，只允许查询、对账或人工处理，不盲目重提。检查点、重试配置和outbox都不能单独保证外部只扣一次费。

| 操作状态 | 允许行为 | 必须保存的证据 |
| --- | --- | --- |
| PENDING | 校验批准、版本、额度并认领 | 操作ID、输入快照、批准版本 |
| SUBMITTING | 发起一次受控外部请求 | 请求标识、执行者、开始时间 |
| RUNNING | 按外部ID查询进度 | 外部ID、下次查询时间 |
| UNKNOWN | 暂停重提，查询或人工核对 | 不确定原因、预留额度、核对过程 |
| SUCCEEDED | 校验并发布当前版本产物 | 文件校验值、清单、实际或估算用量 |
| FAILED或CANCELLED | 保留有效素材，按明确范围恢复或结束 | 失败类别、退款或额度结算依据 |

状态表是操作级模型；整次运行还可处于等待批准或暂停。进入终态要验证业务结果。UNKNOWN不等于失败，也不能为提高成功率统计成成功。

## 版本与并发

批准绑定计划快照、镜头版本、生成范围和预算。计划变化使相关旧批准失效；worker执行前再校验。旧任务晚到只保存旧版本资产，不覆盖当前镜头。镜头修改以原子修订检查提交，冲突返回明确提示。

L3认领机制采用租约和执行代次，写回需匹配当前代次，防止旧worker覆盖新执行者；这不能消除外部副作用，租约失效后的未知提交仍需核对。局部修改先算影响集合，再经用户确认；全局设定变化不能只改被点名的镜头而忽略依赖。

# 七 成本安全与部署

## 预算与供应商接入

可用额度等于预算减去已确认费用及未结清预留。在同一事务内预留额度，L3加入并发竞争测试。UNKNOWN继续占用预留；只有核实未收费、失败退款或结算后才调整。估算与实际收费分列，记录币种、定价版本和用量依据。

首周核实账户可用性、接口、时长档位、画幅、并发、结果保留时间、查询、幂等和取消能力。先生成一个镜头再估算整片费用；预算包括对话、Embedding、视频、重做、存储与部署。不购买长期套餐作为前置条件。

单次收费上界不明确时，不能宣称严格预算保证；显示估算及余量，必要时暂停。自动重试只用于已知可重复的查询等操作。真实API暂时不可用可以用标注清楚的模拟器开发，但真实闭环仍是最终验收条件。

## 安全测试随功能加入

认证从服务端确定用户身份，资源访问逐项检查归属。核心版至少有两个测试账户，覆盖项目、资料、操作和素材下载。资料中的指令与工具返回是非可信数据，不能改变权限、审批和预算。

测试文档诱导跳过审核、伪造工具成功、越权读资料及超大文件。下载需限制域名或可信来源、重定向、内网目标与资源大小；FFmpeg使用固定参数数组，限制路径、时长与进程运行时间，不执行模型生成的任意shell。

## 可观测性与部署验收

统一request_id、run_id、operation_id关联接口、模型、队列和资产日志。记录耗时、错误类别、重试、模型版本、Prompt版本、token及费用，不记录隐藏思维链。日志脱敏并限制资料正文外发；LangSmith故障不能丢失业务事实。

CI执行代码检查、关键单元与集成测试；真实付费测试独立手动触发并限额。Compose完成数据库、Redis、API和worker启动，提供环境示例、健康检查和迁移步骤。公网展示前配置HTTPS和鉴权，演示使用脱敏资料。

L3增加一次备份恢复演练、一次服务重启和一次容量实验。分别测接口、队列和外部供应商耗时；报告环境、样本、并发及错误。小样本不包装为生产容量，不为了写高并发数字增加不必要的基础设施。

# 八 评测与发布门槛

P0建立10个人工样例，P2起每次Agent变更跑开发集。评测把模型决策、确定性业务约束和真实媒体质量分开，避免把供应商生成慢误判为Agent规划失败，也不能从端到端报告删除外部故障。

## 数据集与对照

逐步扩展至60个任务，规划追问、工具审批、局部修改与记忆、检索引用、故障权限各12个；按任务来源和场景拆成40个开发任务与20个独立任务。同一事实问题的改写不得跨集合。另建确定性故障套件。

独立集冻结后每题运行3次，保存全部结果。报告逐次成功率以及同一任务三次全部成功的比例，不能把60次运行说成60个独立任务。失败进入下一版本开发集时，要补充新的独立任务并记录测试集版本。

| 指标 | 口径与检查 | 验收规则 |
| --- | --- | --- |
| 任务成功 | 全部成功条件满足的运行占比 | L3争取≥85%，公布失败和样本量 |
| 关键约束 | 未批准付费、越权、错误版本覆盖 | 指定测试零违规；发现一例就修复 |
| 检索Recall@5 | 前5条命中相关片段数占全部相关片段数，逐题平均 | 报告各方案实测值及空结果任务 |
| 引用正确与覆盖 | 支持陈述的引用比例；需引用陈述中已引用比例 | 正确率争取≥90%，覆盖率必须同时报告 |
| 恢复与局部修改 | 终态、请求次数、重生成集合与清单 | 指定故障和修改矩阵全部通过 |
| 成本耗时 | 模型、排队、生成、下载、拼接分别记录 | 报告样本和中位数，费用区分估算 |
| 内容与人工时间 | 忠实度、连贯性、风格、可用性及修改分钟数 | 人工评分并写原因，模型仅辅助 |

85%和90%是项目自定的拟定目标，不是招聘标准。20个独立任务只够初步暴露问题，不代表广泛泛化能力。不得只报告高分子集或事后降低标准。未达到目标时记录差距并继续改进，不把未达标版本描述为完整达标。

固定流程与Agent使用同样的权限、审批、预算和模型条件，比较自适应决策的实际价值。再分别测试摘要、融合检索和局部复用的收益；一次只改变一个机制，不要求每项实验都得到提升。

核心版至少完成一条真实短片和一次局部修改，明确小样本限制。L3在预算允许下完成6条真实短片与3次局部重做；未达成时注明缺口，不宣称该项验收完成。美感与角色一致性由人工评估，账号增长独立观察。

## 必须运行的业务测试矩阵

每个用例保存输入、注入位置、预期结果、数据库前后状态和外部调用计数。模拟器覆盖不易稳定复现的外部故障，真实API验证接入；两类结果分开。

| 用例 | 核心版要求 | L3深化 |
| --- | --- | --- |
| 缺失需求与工具失败 | 追问或调整，不伪造完成 | 多轮组合失败回归 |
| 未批准或旧批准 | 无新付费提交 | 修改与执行并发时仍拒绝 |
| 只改第三镜头 | 批准范围正确，其他素材不变 | 对照素材校验值与最终清单 |
| 全局设定修改 | 展示影响集合并重新确认 | 检查全部依赖与遗漏 |
| 重复HTTP请求和消息 | 同一操作不新建有效任务 | 跨worker重复投递仍正确 |
| 提交成功但响应丢失 | UNKNOWN暂停，保留额度 | 查询恢复或对账，无盲目重提 |
| 数据库成功但漏发队列 | 持久操作可重新派发 | outbox故障注入与去重 |
| worker中断或旧结果晚到 | 已知任务可恢复，旧版本不覆盖 | 租约过期与旧执行者竞争 |
| 预算耗尽与并发预留 | 超额不提交 | 事务竞争后余额与预留一致 |
| 长对话和设定撤销 | 不使用已撤销要求 | 压缩前后及多次改口回归 |
| 越权和提示注入 | 资料与下载均拒绝越权 | 组合诱导不能绕过审批 |
| 损坏媒体和取消请求 | 不发布坏片，停止未提交工作 | 外部取消和收费状态可核对 |
| SSE断线与模型格式错误 | 重连可查状态，有限修复次数 | 状态回放与超限暂停 |
| MCP错误输入与超时 | 核心版不要求MCP | 发现调用成功，异常和越权可控 |

上述测试中的付费、权限和版本约束是硬门槛；恢复到UNKNOWN属于正确保守处理时，应在结果中明确区分“安全暂停”和“任务完成”。

# 十 独立掌握与第一周任务

每次只推进一个可理解的小目标，先说明业务和文件职责，再实现、运行并核验。AI可解释、评审与排错；核心接口不能只靠复制整段生成代码。以下是学习验收，不是限制日常合理使用AI工具。

| 学习方向 | 当场完成的练习 | 对应阶段 |
| --- | --- | --- |
| Python与HTTP | 独立写一个带校验和错误返回的接口，解释阻塞位置 | P1 |
| SQL与事务 | 复现重复提交或余额竞争，用约束与事务修复 | P1及P6 |
| 工具循环 | 不依赖Agent框架接通工具调用及结果回传 | P2 |
| RAG原理 | 解释一次错检，修改一个参数并比较前后结果 | P2及P6 |
| 状态与版本 | 画出超时和用户改口后的状态转换，解释冲突处理 | P3 |
| 测试调试 | 读失败日志、定位一处错误、补一个有意义的测试 | 每阶段 |
| 工程交付 | 在干净环境启动系统，执行迁移、测试与恢复 | P4及P6 |
| 能力迁移 | 复用工具接口完成资料问答小任务，不复制视频业务代码 | P5 |

每两周安排一次独立验收：可以查文档，在45～60分钟内完成一项小修改并解释设计；时间只用来观察进步，不以一次超时否定能力。把不会的知识写进下一周期的基础练习。

## 第一周按最小依赖顺序推进

第一步：建立Git仓库、虚拟环境、配置与健康检查，启动后能返回状态。第二步：设计users、projects和shots最小字段，说明归属和外键。第三步：写创建项目与查询接口，验证错误参数和不存在的资源。第四步：保存镜头，重启后读取；用第二账户验证拒绝越权。

第五步：验证一个视频供应商。保存能力清单和一次真实任务ID；先以固定输入测试提交、查询、下载和费用，再接业务流程。第六步：整理10个样例，包含资料不足、第三镜头修改和提交结果未知。第一周若基础未过关，就顺延，不跳过解释与验证。

## 基础与专项分开

每周持续练数组、哈希、栈队列、树、复杂度、HTTP、进程线程和数据库基本知识。目标岗位明确要求Java时再开Java与Spring支线；模型算法岗位需要数学、训练和PyTorch等专项，本项目不能代替。不要为了覆盖所有职位同时学习全部分支。
